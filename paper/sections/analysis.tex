\section{Analysis and Discussion}
\label{sec:analysis}

The final results are best explained by a conditional transfer account.
Validated memory is useful when stored learnings describe procedures that recur in held-out tasks and when retrieval relevance tracks that reuse.
It is weak or harmful when memories are too local, when the action context changes, or when denser memory does not improve alignment.

\subsection{Task Compositionality}
\label{sec:compositionality}

ALFWorld tasks decompose into shared sub-goal phases such as searching, acquiring, transforming, and placing objects.
A learning about opening a container, heating an object, or checking receptacles can apply across many held-out tasks.
This compositionality makes cross-task memory useful.

SQL has compositional syntax, but many successful repairs are tied to local schema and predicate choices.
ScienceWorld has procedural motifs, but its category diversity and sparse final KB make the mapping from retrieved learning to held-out task less reliable.
The result is a gradient: strong ALFWorld transfer, narrow SQL transfer, and no promoted ScienceWorld transfer.

\paragraph{Principle.}
Episodic memory is most effective when tasks share reusable sub-procedures rather than merely superficial semantic similarity.

\subsection{Action Space Regularity}
\label{sec:action-space}

ALFWorld's fixed grammar makes action-level reuse tractable.
TR is positive there, and CR+TR is strongest.
SQL also has a regular symbolic language, but correctness depends on exact schema grounding; a memory can suggest the right kind of query while still pushing the agent toward the wrong table, join, or predicate.
ScienceWorld actions and state transitions are more varied, and the final results show that successful retrieval volume is not enough to overcome this mismatch.

\paragraph{Principle.}
Regular action spaces help memory transfer only when the retrieved correction remains valid under the current task's grounding constraints.

\subsection{Learning Transfer Radius}
\label{sec:transfer-radius}

We use \emph{learning transfer radius} to describe how many future tasks can benefit from one stored learning.
ALFWorld has high radius: one correction can apply across many object-location or transformation tasks.
SQL has narrow radius: reusable syntax exists, but individual memories often depend on a particular schema or query intent.
ScienceWorld has uncertain radius under the current retrieval setup: the 1-var final KB and 3-var density gate both fail to produce a reliable CR+TR advantage over ReAct or hard-negative retrieval.

\paragraph{Principle.}
Validated memory should be expected to help most when each stored learning has a broad transfer radius and retrieval can identify that radius before injecting the memory.

\subsection{Why Hard-Negative Controls Matter}
\label{sec:hard-negative-analysis}

Hard-negative retrieval is essential because memory systems can appear to help for reasons unrelated to relevance: longer prompts, extra deliberation cues, or generic reminders.
ALFWorld rejects that alternative explanation: proper CR+TR reaches $82.8\%$, while hard-negative CR+TR drops to $55.2\%$.
SQL and ScienceWorld show the opposite cautionary value.
When hard-negative retrieval is close to or better than proper retrieval, the memory channel has not demonstrated reliable relevance.
This is why ScienceWorld remains diagnostic even after the denser 3-var KB gate.

The practical implication is conservative.
Before deploying memory retrieval, practitioners should ask whether prior corrections are likely to transfer across tasks, whether the action/state representation preserves that transfer, and whether hard-negative controls separate relevant memory from irrelevant context.
If those checks fail, intra-task self-correction, retrieval gating, or stronger validation may be preferable to simply adding more memories.
